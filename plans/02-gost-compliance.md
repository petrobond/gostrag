# Проверка плана на соответствие ГОСТам

| Поле | Значение |
|---|---|
| Проверяемый документ | `plans/01-plan.md` v1.0.0 |
| Дата проверки | 2026-11-11 |
| Метод | Ручная трассировка требований ГОСТов на разделы плана |
| Статус | Выявлены пробелы, внесены правки |

---

## 1. Методология

1. Из каждого стандарта выбраны требования с модальностью «должен / следует / рекомендуется», применимые к программной RAG-системе.
2. Каждое требование сопоставлено с разделом плана.
3. Присвоен статус:
   - **Покрыто** — в плане есть явное действие и артефакт.
   - **Частично** — действие есть, но нет артефакта или критерия.
   - **Пробел** — в плане отсутствует.
4. Для пробелов сформулирована правка, которая внесена в план.
5. Отдельно отмечены стандарты, неприменимые к системе (с обоснованием).

## 4. Альтернативы (с trade-offs)

### 4.1 Judge: собственный vs RAGAS

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Собственный judge на GigaChat (выбран)** | Полный контроль, русский язык, цитаты, JSON | Нужна калибровка, нет готовых метрик |
| RAGAS | Готовые метрики, сообщество | Ориентация на OpenAI, хуже с русским, зависимость |

**Решение:** собственный judge; концепции RAGAS-метрик воспроизводим.

### 4.2 Векторное хранилище: Qdrant vs pgvector

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Qdrant (выбран)** | Быстрый ANN, фильтры, масштабирование | Ещё один сервис |
| pgvector | Один Postgres, меньше сервисов | Медленнее, хуже фильтры |

**Решение:** Qdrant; при упрощении локального стека допустим pgvector.

### 4.3 Эмбеддинги: GigaChat vs Cloud.ru bge-m3 vs локальные

| Вариант | Цена/1M | Плюсы | Минусы |
|---|---|---|---|
| **GigaChat (выбран)** | 14 ₽ | Единый контур, русский, 2048 dim | Дороже bge-m3 в 23 раза |
| Cloud.ru bge-m3 | 0.61 ₽ | Дёшево, 1024 dim, 8192 контекст | Другой провайдер |
| Локально bge-m3 | 0 ₽ | Нулевая цена, контроль | +2.5 ГБ RAM, CPU-инференс |

**Решение:** GigaChat для простоты; при росте объёма — миграция (потребует переиндексации).

### 4.4 Sparse: BM25 + pymorphy3 vs sparse-векторы Qdrant

| Вариант | Плюсы | Минусы |
|---|---|---|
| **BM25 + pymorphy3 (выбран)** | Русская морфология, прозрачность | Отдельный индекс, память |
| Sparse-векторы Qdrant | Один сервис | Хуже для русского без спец. моделей |

**Решение:** BM25; sparse — оптимизация позже.

### 4.5 Чанкинг: структурный parent-child vs contextual retrieval

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Структурный parent-child (выбран)** | Точные цитаты, дёшево | Меньше контекста в чанке |
| Contextual Retrieval (Anthropic) | +качество retrieval | Дороже: генерация контекста на чанк |

**Решение:** структурный; contextual retrieval — эксперимент на этапе 7.

### 4.6 Fallback: DeepSeek vs локальная модель

| Вариант | Плюсы | Минусы |
|---|---|---|
| **DeepSeek YC (выбран)** | Дёшево, 1M контекст, без GPU | Платно, внешний провайдер |
| Локальная 7B | Бесплатно | Нужен GPU/16 ГБ RAM, хуже качество |

**Решение:** DeepSeek; локальная — при требовании офлайн-работы.

### 4.7 Упрощение стека: Redis vs Postgres-only

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Redis (выбран)** | Быстрый кэш и локи, TTL | Ещё один сервис |
| Postgres-only | Меньше сервисов | Медленнее, нужны блокировки |

**Решение:** Redis; для минимального стека допустим Postgres-only.

## 5. Вывод

План v1.0.0 **в целом соответствует** применимым ГОСТам, но требовал 14 правок. Все правки внесены в `plans/01-plan.md` (разделы 2.4, 6.8–6.14, 12.2) и в перечень артефактов (`docs/glossary.md`, `docs/data_quality.md`, `docs/test_plan.md`, `docs/tz.md`, `docs/trust.md`, `docs/impact.md`, `docs/scope.md`).

**Не применимые стандарты:** ПНСТ 1046, ПНСТ 836, ГОСТ Р 71562 — обоснования в `docs/scope.md`.

**Ограничение:** аудит внутренний; LLM-as-a-judge не заменяет эксперта и не является сертификацией.
