# Происхождение данных (ПНСТ 847—2023)

## 1. Модель provenance

Каждый чанк содержит блок `provenance`:

```json
{
  "file": "gost-r-71540-2024.pdf",
  "parser": "pymupdf",
  "parser_version": "2.1",
  "extracted_at": "2026-11-11T18:45:44Z",
  "source_span": "gost-r-71540-2024#8.3.4",
  "owner": "corpus-admin",
  "review_status": "approved"
}
```

## 2. Цепочка прослеживаемости

```
Исходный PDF (data/source)
  → извлечение PyMuPDF (страница, bbox, цвет)
  → очистка (удаление водяных знаков)
  → парсинг (раздел, пункт, страница)
  → чанкинг (chunk_id = doc#clause)
  → эмбеддинг и индекс (Qdrant + BM25)
  → ответ и цитата (ГОСТ, пункт, страница)
```

## 3. Обязательные поля цитаты

| Поле | Назначение |
|---|---|
| `gost` | Номер стандарта |
| `clause` | Номер пункта |
| `page` | Страница |
| `quote` | Фрагмент текста, подтверждающий утверждение |
| `valid` | Прошла ли цитата проверку по корпусу |

## 4. Ответственность

| Роль | Ответственность |
|---|---|
| corpus-admin | Комплектование, очистка, версия корпуса |
| developer | Парсер, индекс, обновления |
| auditor | Проверка provenance и отчёта |

## 5. Ссылки на источник

Каждая цитата в Telegram содержит ссылку на PDF в Object Storage:

```
https://storage.yandexcloud.net/<bucket>/gost/ai_gost_1/<file>.pdf?X-Amz-...#page=<page>
```

- Ссылка генерируется как presigned URL (SigV4, TTL 7 дней).
- Якорь `#page=N` открывает PDF на нужной странице.
- Объекты в бакете не изменяются и не удаляются.
- Соответствие «имя файла → ключ» строится при старте бота.

## 6. Ограничения

- `extracted_at` фиксирует время индексации, а не дату публикации стандарта.
- `review_status` выставляется вручную для новых документов.
- При изменении парсера требуется переиндексация и новая версия корпуса.
