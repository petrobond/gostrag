## Что сделано

### 1. Морфология ГОСТов

Единый regex теперь понимает падежные формы:

- `в ГОСТе Р 71476`;
- `по ГОСТу Р 71476`;
- `из ГОСТа Р 71476`;
- `ГОСТом Р 71476`;
- `ПНСТом 963`;
- полные и короткие номера, год и без года.

`extract_gosts()` и `Retriever._extract_reference()` используют один
канонический regex из `app/rag/gost_refs.py`.

### 2. Каталог терминов из корпуса

`app/rag/term_catalog.py` строит каталог из `chunks.jsonl`:

- ГОСТ Р 71476—2024 — **105 терминов**, 7 подразделов 3.1–3.7;
- термин, определение, пункт, страница, файл;
- 7 секционных цитат;
- каталог обновляется вместе с корпусом, без ручного списка.

`terms.jsonl` для этого не используется: в нём только 5 заголовков
подразделов 71476, а не 105 определений.

### 3. Adaptive planner

`app/rag/adaptive.py` — bounded planner для term-инструментов:

- `term_inventory` — полный список терминов, детерминированно;
- `term_subset` — семантический поднабор по критерию вопроса;
- остальные вопросы идут по существующему fast-path/RAG;
- нет попытки перечислить все возможные интенты.

### 4. LLM-listwise selection

`app/rag/term_selector.py`:

1. embedding-ранжирование 105 терминов по `term + definition`;
2. top-25 кандидатов;
3. LLM выбирает 5–8 терминов под критерий вопроса (JSON);
4. выбираются только `clause` из каталога;
5. ответ строится из точных определений, а не из пересказа LLM;
6. при сбое LLM — top semantic candidates с пометкой fallback.

Пример:

```text
«Какие термины ГОСТа Р 71476 характеризуют ИИ-систему как целое?»
→ 5 терминов, 5 валидных цитат, все из ГОСТ Р 71476—2024.
```

### 5. Роутинг в AskService

- `term_inventory` — 0 LLM, 7 цитат;
- `term_subset` — LLM selector, точные определения;
- `definition` — существующий `find_term` с exact-фильтром;
- при отсутствии каталога/терминов — обычный RAG;
- никаких изменений Qdrant/BM25, переиндексация не нужна.
